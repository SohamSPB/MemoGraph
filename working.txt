WORKING NOTES FOR MEMOGRAPH PIPELINE
====================================

This file summarizes how the MemoGraph pipeline is structured, key tuning
options, and operational patterns (resetting, resuming, comparing runs). It
is meant as a quick reference for future work.

1. Pipeline entrypoint and modes
--------------------------------
- Main entry: run_all.py
  - Usage:
    - Sequential (top-level steps): python run_all.py <trip_folder>
    - Parallel (internal parallelism inside steps):
      - Linux/macOS:   MEMOGRAPH_PARALLEL_EXECUTION=true python run_all.py <trip_folder>
      - Windows PowerShell: $env:MEMOGRAPH_PARALLEL_EXECUTION = "true"; python run_all.py <trip_folder>
    - Reset + rerun:   python run_all.py <trip_folder> --reset
    - Reset only:      python run_all.py <trip_folder> --reset-only

- With --reset / --reset-only:
  - run_all.py removes <trip_folder>/MemoGraph if it exists.
  - --reset then runs the full pipeline with the current configuration.
  - --reset-only exits immediately after deletion (no processing).

2. High-level step flow
-----------------------
For a given trip_folder (e.g. data/trips/2025_Annapurna_Nepal):

1) image_scanner.scan_images(trip_folder)
   - Scans trip_folder for image files matching CFG.IMAGE_EXTENSIONS.
   - Collects all paths, sorts them by relative path for deterministic order.
   - Extracts EXIF (datetime_original, device_model, gps_lat, gps_lon).
   - Writes <trip_folder>/MemoGraph/labels.csv using CFG.CSV_HEADERS.

2) trip_day_assigner.assign_days(trip_folder)
   - Uses datetime_original to compute day_number per image.

3) location_resolver.fill_location(trip_folder)
   - Converts GPS coordinates into location_inferred (strings).
   - After this, run_all generates an initial trip_map.html preview so you
     can open the map while heavier steps continue.

4) Core analysis (top-level sequential, internal parallelism allowed):
   - face_detector.process_faces(trip_folder)
     - Uses face_recognition (CNN/HOG) to set faces_detected (0/1).
     - Batches sized via CFG.FACE_DETECTION_BATCH_SIZE.
     - Avoids heavy nested process pools unless CFG.FACE_DETECTION_PARALLEL_WORKERS > 1.
   - image_labeler.label_images(trip_folder)
     - Uses CLIP with a curated concept list to populate detected_objects.
     - Also writes coarse species-like tags (e.g. "a bird", "a flower") into species_tags.
   - caption_filler.fill_captions(trip_folder)
     - Uses BLIP to generate multiple captions per image.
     - Passes raw BLIP strings through utils_text.clean_caption and
       utils_text.clean_caption_list so `caption` and `caption_samples`
       are less noisy and more readable.
     - Updates caption + caption_samples.
     - Respects CFG.CAPTION_PARALLEL_WORKERS for thread count.
     - Skips rows that already have caption and periodically flushes CSV.
   - generate_ai_captions.generate_ai_captions(trip_folder)
     - Uses BLIP to generate single AI captions.
     - Cleans them via utils_text.clean_caption before saving as caption_ai.
     - Skips rows that already have caption_ai and flushes CSV periodically.
   - species_detector.process_species(csv_path, trip_folder, log_path)
     - Uses CLIP with species_prompts (small list of species names) to refine species_tags.
     - Only overwrites species_tags when it has confident matches; otherwise, keeps coarse tags.
   - image_type_detector.detect_image_types(trip_folder)
     - Uses CLIP zero-shot prompts to assign a coarse image_type per image
       (natural_photo, document_scan, meme_or_graphic, screenshot,
       chart_or_plot).
     - Skips rows where image_type is already set so it can be re-run
       safely.

5) blog_generator.generate_blog(trip_folder)
   - Builds blog.md and trip_summary.json inside MemoGraph.
   - Uses utils_text helpers (clean_caption, clean_caption_list,
     combine_captions_for_day, clean_species_list) to produce smoother daily
     summaries from caption/caption_ai fields.
   - Builds per-day paragraphs that:
     - Use start/end times and locations (shortened for readability).
     - Derive coarse themes (mountains, water, towns, temples/monuments,
       markets, food, stays, astro, wildlife, roads/trails) from
       detected_objects + captions + image_type.
     - Mention wildlife using cleaned, biological species names while
       filtering out non-biological tags like "galaxy" and "nebula".
     - Use varied intro/scene phrases so days do not all start with the
       exact same sentence.
   - The resulting blog is intentionally template-based and deterministic so
     it can be used both as a quick summary and as input to external LLMs
     (see blog_generation_prompt.md) for richer rewrites.

6) map_visualizer.create_map(points, map_path)
   - Produces the final interactive map (trip_map.html) after all fields
     (captions, species, image_type, etc.) are available.
   - run_all also calls map_visualizer.create_overview_page(trip_folder) to
     build trip_overview.html, which embeds trip_map.html and shows any
     photos without GPS coordinates in a sidebar so the user can still see
     them in the same page.

7) build_blog_context.build_blog_context(trip_folder, include_extras=False)
   - Reads <trip>/MemoGraph/labels.csv and builds a richer JSON description:
     - Per-day start/end times and shortened locations.
     - Per-day themes and simple activity strings (e.g. mountain roads,
       markets/bazaars, temples/monasteries, food/tea breaks, stays,
       astro/night-sky, wildlife).
     - Per-image summaries (time, location, caption/caption_ai, species_tags,
       detected_objects, image_type, faces_detected, plus optional YOLO
       objects and Places365 scene tags when the corresponding models are
       available under models/yolo and models/places.
   - Heavy extras (YOLO, EasyOCR, Places365) are gated by
     `BLOG_CONTEXT_INCLUDE_EXTRAS` (default False). Command line:
       `python -m scripts.build_blog_context <trip> --include-extras`
     enables them on demand; `--skip-extras` forces them off.
   - Writes <trip>/MemoGraph/blog_context.json, designed to be fed into an
     external text-generation model to produce a more natural, narrative blog.

8) build_webapp.build_webapp(trip_folder)
   - Loads blog_context.json and emits a static gallery/map app at
     <trip>/MemoGraph/webapp/index.html with inline data + Leaflet.
   - Generates JPEG thumbnails (CFG.THUMBNAIL_MAX_SIZE) under
     <trip>/MemoGraph/thumbnails to keep the UI fast; gallery and map popups
     load thumbnails first and fall back to originals only if needed.
   - Web app behaviour:
     - Search bar: matches captions, AI captions, species_tags, detected_objects,
       YOLO objects, Places365 scenes, people_tags, and location strings.
     - Filter chips: built from CLIP/YOLO/Places tags (birds, plants, astro,
       landscapes, etc.) with a collapse/expand toggle, quick preset buttons
       (Birds, Landscapes, Astro, People), and per-trip custom presets stored
       in localStorage.
     - Gallery: displays thumbnails with captions + tags; all images respond
       to search/chip filters and show the full-resolution photo + metadata
       inside a lightbox that now includes keyboard navigation, copy/open
       buttons, device info, faces/species/objects/scene tags, and a mini-map.
       A filmstrip is permanently docked across the bottom so you can scrub like a
      native photo app.
      - Quality-aware browsing: a “Best Balanced” toggle filters/sorts by the new
        `quality_score`, gallery cards show the percentage, and lightbox metadata
        lists exposure/contrast/sharpness/noise sub-metrics + human-readable notes.
     - Map: Leaflet map shows only the filtered GPS-tagged photos with
       captions + thumbnails inside popups, plus quick previews when multiple
       shots share the same rounded lat/lon (coarse clustering).
     - Header: shows the trip name and a back button that jumps to the master
       trips hub (`../../index.html`) for multi-trip navigation.

9) build_trip_index.build_trip_index(trips_root)
   - Scans data/trips for MemoGraph outputs and renders a master landing page
     at data/trips/index.html.
   - Each trip card displays stacked thumbnails (from MemoGraph/thumbnails),
     the date range, day/photo counts, and top themes/species derived from
     blog_context.json, linking into that trip’s webapp/index.html.
   - run_all.py calls this after every trip so the hub stays in sync.

Optional: Face recognition
   - build_face_gallery.build_face_gallery(known_root, gallery_path):
     - Scans models/faces/known/<PersonName>/ for reference photos.
     - Uses face_recognition to extract clean face encodings for each person.
     - Writes a gallery pickle to CFG.FACE_GALLERY_PATH
       (default models/faces/face_gallery.pkl).
   - face_recognizer.recognise_faces(trip_folder):
     - Loads the gallery and labels.csv for the trip.
     - For rows where faces_detected indicates faces, re-runs encoding and
       matches against the gallery using FACE_RECOGNITION_THRESHOLD.
     - Writes recognised names into the people_tags column in labels.csv.
   - Controlled via memograph_config:
     - ENABLE_FACE_RECOGNITION = True/False
     - FACE_GALLERY_PATH, FACE_RECOGNITION_THRESHOLD.

Resource logging
   - run_all.py records CPU/RAM/GPU usage and writes MemoGraph/logs/resource_usage.csv.

3. Image resolution and performance knobs
-----------------------------------------
- MAX_IMAGE_SIZE (memograph_config.py)
  - Global maximum size (longest side) for images sent to models (CLIP/BLIP/face recognition).
  - Lower values (e.g. 256 or 512):
    - Reduce memory and speed up processing.
    - May slightly change CLIP/BLIP outputs.
  - Higher values (e.g. 1024):
    - Better detail for models.
    - Heavier on CPU/GPU and RAM.
- THUMBNAIL_MAX_SIZE / THUMBNAIL_SUBDIR (memograph_config.py)
  - Controls the resolution + folder for JPEG thumbnails generated by build_webapp.
  - Defaults to 320px previews stored in <trip>/MemoGraph/thumbnails and referenced by the gallery + map popups inside the static web UI.

- Parallelism knobs (memograph_config.py):
  - PARALLEL_WORKERS: legacy knob (currently unused for top-level steps; high-level steps now run sequentially in run_all.py).
  - FACE_DETECTION_BATCH_SIZE: images per batch in face_detector.
  - FACE_DETECTION_PARALLEL_WORKERS: inner process workers inside face_detector (default 1).
  - CAPTION_PARALLEL_WORKERS: thread count for BLIP captioning (caption_filler).

- Resource thresholds:
  - MIN_AVAILABLE_RAM_MB / MIN_AVAILABLE_GPU_MEM_MB:
    - Used by utils_resources.check_resources before enabling parallel mode.

- CSV schema:
  - Core fields (image_name, local_path, md5sum, datetime_original, device_model,
    gps_lat, gps_lon, location_inferred, day_number, detected_objects,
    species_tags, faces_detected, people_tags, caption, caption_ai, notes).
  - `image_type`:
    - Coarse content type classification, e.g.:
      - natural_photo, document_scan, meme_or_graphic, screenshot, chart_or_plot.
    - Populated by scripts/image_type_detector.py using CLIP zero-shot prompts.

4. Robustness, resume behavior, and incremental saving
------------------------------------------------------
- Stable ordering:
  - image_scanner writes labels.csv in a sorted order by relative path.

- Captioning scripts:
  - caption_filler.py:
    - Skips rows where caption is already non-empty.
    - In parallel mode, flushes labels.csv after ~10 completed futures.
    - In sequential mode, flushes after every 10 processed rows.
  - generate_ai_captions.py:
    - Skips rows where caption_ai is already non-empty.
    - Flushes labels.csv after every 10 processed rows.

- Practical effect:
  - You can stop a run (e.g. crash/power loss) and rerun caption_filler or
    generate_ai_captions; they will only process missing captions and
    preserve prior work.
  - At most ~10 images’ worth of new captions are lost if a run ends abruptly.

- Future pattern (not yet applied to all steps):
  - Apply similar "skip processed rows + periodic flush" to face_detector,
    image_labeler, and species_detector.
  - Optionally add *_done flag columns (faces_done, labels_done, etc.) to
    make pause/resume semantics explicit.

5. Resolution comparison workflow
---------------------------------
- To compare behavior at different MAX_IMAGE_SIZE values for a given trip:
  - Run pipeline at MAX_IMAGE_SIZE=256, then rename MemoGraph to MemoGraph_256.
  - Run at 512, rename to MemoGraph_512.
  - Run at 1024, rename to MemoGraph_1024.

- Use scripts/compare_resolutions.py:
  - Example: python -m scripts.compare_resolutions data/trips/2025_Annapurna_Nepal
  - Reports whether fields like faces_detected, species_tags, detected_objects,
    caption, caption_ai match across variants and where they first diverge.

6. Species detection (current & future)
---------------------------------------
- Current:
  - Coarse labels:
    - image_labeler uses CLIP to add "a bird", "an insect", "a dog", etc. to
      detected_objects and species_tags.
  - Fine-grained labels (limited):
    - species_detector uses CLIP + species_prompts (hard-coded list of species
      names) to optionally refine species_tags when confident.
    - Cannot output names that are not in species_prompts.

- Future (not implemented here, but planned in task.txt):
  - Use coarse tags (bird/insect/animal/plant) as triggers to call specialist
    models (e.g. iNaturalist-based bird classifiers) stored under models/.
  - Merge those predictions into species_tags while preserving coarse tags as
    fallback.

7. Resetting and reprocessing trip data
---------------------------------------
- When models or configuration improve and you want to regenerate all outputs:
  - Use: python run_all.py <trip_folder> --reset
  - This deletes <trip_folder>/MemoGraph and runs the full pipeline again.
  - Existing manual variants (MemoGraph_256/512/1024) are not touched.

9. Additional comparison tools and stats (added)
-----------------------------------------------
- scripts/compare_stats.py:
  - Example:
    - python -m scripts.compare_stats data/trips/2025_Annapurna_Nepal --variants MemoGraph_256_2 MemoGraph_512_2 MemoGraph_1024_2
  - Reads each MemoGraph_*/logs/resource_usage.csv and prints a table of:
    - step, then <variant>:cpu_percent, <variant>:ram_mb, <variant>:gpu_mb.
  - CPU% values can exceed 100 because they represent combined usage across all cores for the process tree (e.g. ~600% ≈ 6 cores).

- scripts/compare_labels_variants.py:
  - Example:
    - python -m scripts.compare_labels_variants data/trips/2025_Annapurna_Nepal --variants MemoGraph_256_2 MemoGraph_512_2 MemoGraph_1024_2 --fields detected_objects species_tags caption caption_ai
  - Prints a CSV-style table with one row per image and columns for <variant>:<field>, useful for checking stability of CLIP/BLIP outputs across resolutions/runs.

- stats_256.txt, stats_512.txt, stats_1024.txt:
  - Plain-text summaries of per-step timings and RAM usage for the latest _2 runs at each resolution, based on run_all.log and resource_usage.csv.

10. Species gating to avoid false positives (added)
--------------------------------------------------
  - species_detector.py now:
    - Builds a coarse text string from detected_objects + caption + caption_ai for each image.
    - Only runs CLIP species matching when that text contains biological hints (bird/animal/plant/insect and related terms).
    - If no such hints are found (e.g. pure galaxy/nebula images), species detection is skipped and existing tags are preserved.
    - This prevents unrealistic species predictions (e.g. Peacock/Owl on space photos) and relies on image_labeler + captions to indicate when biological species are present.

11. GPS propagation and inferred locations (added)
--------------------------------------------------
- Purpose:
  - Many phones/cameras intermittently miss GPS for some photos in a trip, even though nearby images are geotagged.
  - To avoid fragmenting the map and leaving large gaps, we infer GPS for images taken close in time to a geotagged photo.

- Behavior:
  - location_resolver.fill_location(trip_folder):
    - Reads datetime_original and GPS fields from labels.csv.
    - Walks rows in chronological order and, when it finds an image without GPS but within a configured time window of the previous geotagged image, copies that previous GPS.
    - The time window is controlled by a config knob in memograph_config.py (e.g. GPS_PROPAGATION_MAX_MINUTES, default ~15).
  - Effect:
    - Images taken a few minutes before/after a geotagged shot will appear on the map at a sensible location.
    - location_inferred is then filled using the real or propagated GPS coordinates, so downstream text (blog/map popups) remains consistent.

12. Overview page, tags, and UI templates (added)
-------------------------------------------------
- Overview page:
  - After the final map is generated, run_all.py calls map_visualizer.create_overview_page(trip_folder).
  - This produces trip_overview.html, which:
    - Embeds trip_map.html on the left side.
    - Shows all photos without GPS coordinates in a right-hand sidebar as card-style thumbnails.
    - Uses lazy-loading (img loading="lazy") so large trips are more responsive.

- Tags and filters:
  - For each non-GPS image, the overview builder infers a small set of tags based on:
    - detected_objects, species_tags, image_type, faces_detected, and captions.
  - Typical tags include:
    - people, birds, plants_flowers, insects, animals, landscapes, astro, plus image_type categories (natural_photo, document_scan, meme_or_graphic, screenshot, chart_or_plot).
  - At the top of the sidebar, a filter bar renders each tag as a chip-like toggle:
    - Clicking a chip shows only images that have that tag (OR semantics across chips).
    - A "Clear filters" action resets to showing all sidebar images.

- UI templates and theming:
  - A reusable CSS theme is stored under templates/memograph_ui.css.
 - map_visualizer.create_overview_page copies this file into <trip>/MemoGraph as memograph_ui.css and links it from trip_overview.html.
  - The CSS defines a dark, Material-style look (app bar, cards, chips, buttons) applied to the overview layout.
  - This template-based approach makes it easier to tweak colors/spacing/animations once and have all future trips use the updated styles.

13. Web app backlog and polish items
------------------------------------

- scripts/vision_llm_demo.py:
  - Tiny helper to test multimodal LLMs (e.g. llava-hf/llava-onevision-qwen2-0.5b-ov-hf).
  - Setup:
    1. `.venv\Scripts\Activate.ps1`
    2. `hf auth login --token <HF_TOKEN>`
    3. Download once (≈1.6 GB to fetch, expands to ~12.8 GB on disk, ~8-9 min):
       ```powershell
       python - <<'PY'
       from huggingface_hub import snapshot_download
       snapshot_download(
           'llava-hf/llava-onevision-qwen2-0.5b-ov-hf',
           local_dir='models/llava_onevision_qwen2_0.5b'
       )
       PY
       ```
  - CLI:
    ```
    python -m scripts.vision_llm_demo data/trips/<trip> ^
      --model-id models/llava_onevision_qwen2_0.5b ^
      --question "Describe the scene."
    ```
  - Automatically resizes the chosen image to <=512 px, feeds it to the model, prints the
    result, and saves `<trip>/MemoGraph/llm_vision_demo.txt`. Pass `--image` for a specific
    file or rely on the first non-MemoGraph photo. Toggle max tokens via `--max-new-tokens`.
  - Inference time on GTX 1650: ~40 s/image after the first load.
  - Sample outputs:
    - Annapurna IMG20240816111741: tree with orange fruits by a white wall/green roof.
    - Home IMG20251019232730: indoor telescope on tripod by checkered curtain, cabinet with pink blanket/striped pillow.
